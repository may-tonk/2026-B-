# 2026 电工杯 B 题项目阶段实施手册

## 1. 文档目的

本手册用于指导 `B题：嵌入式社区养老服务站的建设与优化问题` 的建模、编程、写作和结果核验工作。项目采用分阶段推进方式：

1. 先统一数据口径与关键假设。
2. 再建立老人数量与服务需求预测模型。
3. 再基于预测需求完成服务站选址、规模与覆盖分配。
4. 在站点方案固定后完成服务定价与政府补贴优化。
5. 最后复用前述模型完成灵敏度分析、方案比较与模型评价。

本手册采用以下基本原则：

- 求解模块不得直接读取原始附件，统一通过数据预处理模块取得标准化参数。
- 各问题的输入输出应形成清晰的数据流，避免同一指标在不同阶段含义混乱。
- 先严格满足题目与附件给出的规则，再考虑可选扩展模型。
- 模型结果、代码输出、论文表述三者必须使用同一口径。

## 2. 题目输入与统一口径

### 2.1 原始附件

本题当前工作区包含题目 PDF 与附件 1-5。附件中的核心工作表共 8 张：

| 附件 | 工作表 | 主要内容 |

| 附件 1 | 转移概率 | 自理向半失能、半失能向失能的年度转移概率 |
| 附件 2 | 每位老人月均服务需求次数 | 3 类老人对 6 项服务的月需求频次 |
| 附件 2 | 服务营收及支出 | 单次服务营收、单次直接支出 |
| 附件 2 | 月服务消费上限 | 各类老人的收入消费上限比例 |

### 2.2 术语口径

后续文档、代码与论文统一使用下列术语：

| 术语 | 含义 |
| --- | --- |
| 理论服务需求 | 不考虑消费能力与满意度折减的服务需求 |
| 消费约束后需求 | 按月服务消费上限进行削减后的服务需求 |
| 实际有效服务人次 | 按题目规则由服务需求乘以满意度得到的有效服务量 |
| 覆盖率 | 至少享受一项养老服务的老人数占老年总人口比例 |
| 服务量完成指标 | 实际有效服务人次与消费约束后需求人次的比例，可作为辅助指标 |

必须避免以下混用：

- 不将消费约束后需求直接称为实际有效服务人次。
- 不将服务人次比例直接替代题目定义的老人覆盖率。
- 不将紧急救助作为可自主定价服务。

### 2.3 关键假设锁定

基础模型建议采用以下假设：

1. 年均新增老人占当年老年人口的比例为题设值，新增老人初始进入自理老人状态。
2. 年均自然死亡率对三类老人统一作用。
3. 自理老人只可能转移为半失能老人，半失能老人只可能转移为失能老人，失能老人不恢复。
4. 题目给出的月均服务需求频次在预测期内保持稳定。
5. 消费约束严格按附件 2 处理：当某类老人理论月服务费用超过其月消费上限时，各项服务次数等比例削减。
6. 模型内部尽量保留连续需求值，输出表格时再统一执行取整规则。
7. 站点容量以人次/日计量，需求预测先以人次/月输出，再按统一时间口径转换为人次/日。
8. 问题 2 中服务价格先按基准定价口径处理，问题 3 再优化除紧急救助外的 5 项付费服务价格。
9. 问题 3 中“保本微利”按利润率闭区间处理：

   \[
   0 \leq \text{利润率} \leq 8\%
   \]

### 2.4 需要尽早确定的计算口径

项目开工前应由全队确认并写入代码配置：

| 口径 | 建议 |
| --- | --- |

| 需求取整 | 模型内部保留小数，题目要求展示时四舍五入 |
| 价格基准 | 依据附件 2 和附件 5 统一解释，代码中只保留一处基准价定义 |
| 问题 2 综合目标 | 建议采用分层优化，先覆盖率后满意度；若加权，需记录权重 |
| 问题 3 定价范围 | 设定合理上下界，且紧急救助价格恒为 0 |
| 补贴核算时间 | 先按日上限核算，再换算年度补贴 |

#### 4.3.2 建立字段校验

至少检查以下内容：

| 检查项 | 说明 |
| --- | --- |
| 小区编号 | 是否恰好包含 A-J |
| 老人结构 | 自理、半失能、失能人数之和是否等于 60+ 老人数 |

| 满意度规则 | 分段边界是否完整 |

#### 4.3.3 生成状态转移矩阵

健康状态顺序统一为：

```text
[自理, 半失能, 失能]
```

基础状态转移矩阵可写为：

\[
P=
\begin{bmatrix}
1-p_{12} & p_{12} & 0 \\
0 & 1-p_{23} & p_{23} \\
0 & 0 & 1
\end{bmatrix}
\]

其中：

- \(p_{12}\) 为自理向半失能转移概率。
- \(p_{23}\) 为半失能向失能转移概率。

这里的 \(P\) 只描述存活老人内部健康状态转移，死亡率在递推式中单独处理。因此应检查 \(P\) 的每行和为 1。

#### 4.3.4 生成距离网络对象

建议同时保留三种对象：

1. `distance_matrix`：原始距离矩阵。
2. `coverage_mask`：1000 米内是否可达的 0-1 矩阵。
3. `filtered_distance_matrix`：超过 1000 米置为正无穷的求解矩阵。

这样既能完成硬约束过滤，也不丢失原始距离信息。

## 5. 阶段一：老人数量与服务需求预测

### 5.1 阶段目标

完成问题 1：

1. 预测第 1 年至第 5 年末每个小区三类老人数。
2. 计算第 5 年末各小区理论月服务需求。
3. 在消费能力约束下得到消费约束后需求。

### 5.2 阶段输入

- 阶段零输出的人口初始矩阵。
- 健康状态转移矩阵 \(P\)。
- 死亡率与新增老人比例。
- 单人月均服务需求频次矩阵。
- 人均月收入与消费上限比例。
- 服务价格口径。

### 5.3 数量递推模型

对每个小区单独预测。设第 \(t\) 年老人结构向量为：

\[
N_t = [A_t, H_t, D_t]
\]

其中：

- \(A_t\)：自理老人数量。
- \(H_t\)：半失能老人数量。
- \(D_t\)：失能老人数量。

当年总老人数为：

\[
T_t = A_t + H_t + D_t
\]

新增老人向量为：

\[
B_t = [gT_t, 0, 0]
\]

其中 \(g\) 为新增老人比例。自然死亡率记为 \(d\)。递推式为：

\[
N_{t+1} = (1-d)N_tP + B_t
\]

基础场景参数：

- \(d = 0.05\)。
- \(g = 0.07\)。

### 5.4 理论需求计算

设第 5 年末小区 \(i\) 的老人结构为：

\[
N_{i,5} = [A_{i,5},H_{i,5},D_{i,5}]
\]

设单人月需求频次矩阵为 \(R\)，其行对应老人类型，列对应服务项目。理论月需求矩阵为：

\[
Q_i^{theory} = N_{i,5}R
\]

输出层面需要能分别展示：

- 按小区汇总。
- 按服务项目汇总。
- 按老人类型拆分。

### 5.5 消费约束处理

对小区 \(i\)、老人类型 \(k\)，先计算该类老人单人理论月服务费用：

\[
E_{ik}=\sum_s r_{ks}p_s
\]

其月消费上限为：

\[
L_{ik}=\alpha_k \cdot income_i
\]

其中：

- 自理老人 \(\alpha_k=20\%\)。
- 半失能老人 \(\alpha_k=25\%\)。
- 失能老人 \(\alpha_k=30\%\)。

消费约束比例为：

\[
\lambda_{ik}=\min\left(1,\frac{L_{ik}}{E_{ik}}\right)
\]

消费约束后单人服务需求为：

\[
r'_{ks}=\lambda_{ik}r_{ks}
\]

消费约束后小区需求为：

\[
Q_i^{payable}=\sum_k N_{i,5,k}r'_{ik}
\]

本阶段不得将消费约束改写为自定义服务优先级削减，除非在扩展模型中另行论证并与基础模型区分。

## 6. 阶段二：服务站选址、规模与覆盖分配

### 6.1 阶段目标

完成问题 2：

1. 在预算与服务半径约束下选择站点位置。
2. 为每个站点选择小、中、大规模。
3. 确定小区到站点的服务归属。
4. 计算覆盖率、满意度、年度利润和站点利用率。

### 6.2 阶段输入

- 第 5 年消费约束后日需求矩阵。
- 第 5 年老人数量预测结果。
- 站点建设成本、固定运营成本、容量。
- 距离矩阵与覆盖矩阵。
- 满意度评分规则。
- 建设预算 120 万元。

### 6.3 模型定位

本阶段模型建议表述为：

> 预算约束下的多规模容量限制覆盖选址模型。

它可借鉴最大覆盖选址思想，但必须显式包含：

- 多规模站点选择。
- 建设预算。
- 1000 米服务半径。
- 容量上限。
- 老人选择满意度最高站点规则。
- 综合满意度评价。

### 6.4 决策对象

建议使用以下决策对象：

| 对象 | 含义 |
| --- | --- |
| 站点位置 | 在 A-J 哪些小区建站 |
| 站点规模 | 不建、小型、中型、大型 |
| 小区归属 | 每个小区最终由哪个可达站点服务 |
| 站点服务量 | 各站点承担的实际有效服务人次 |

### 6.5 基础约束

#### 6.5.1 预算约束

\[
\sum_j build\_cost_j \leq 120
\]

建设成本单位应在代码中统一。

#### 6.5.2 半径约束

若小区 \(i\) 到站点 \(j\) 的距离大于 1000 米，则小区 \(i\) 不可由站点 \(j\) 服务。

#### 6.5.3 容量约束

站点承担的服务量不得超过对应规模的人次/日容量。

基础模型建议将超载方案视为不可行方案。若后续希望允许部分需求失配，需要额外定义分配规则并单独说明。

#### 6.5.4 归属规则

老人只选择满意度最高的服务站。若多个站点满意度相同，应在代码中固定并记录并列处理规则，例如：

1. 先选择距离更近者。
2. 若仍相同，选择容量余量更大者。
3. 若仍相同，按小区编号顺序稳定选择。

### 6.6 满意度处理

总满意度为：

\[
S = 0.2S_1 + 0.3S_2 + 0.5S_3
\]

其中：

- \(S_1\) 由距离分段决定。
- \(S_2\) 由站点利用率分段决定。
- \(S_3\) 由价格分段决定。

问题 2 中建议先固定价格口径，从而固定 \(S_3\)。由于 \(S_2\) 与站点利用率相关，单个候选选址方案的评分至少应完成以下过程：

1. 根据距离约束获得可达站点集合。
2. 给出初始归属方案。
3. 计算各站点承担需求和利用率。
4. 计算响应满意度 \(S_2\)。
5. 更新总满意度与归属。
6. 在归属稳定或达到指定迭代次数后评估该方案。

若采用一次近似而非迭代，也必须在论文中明确说明。

### 6.7 目标设计

题目要求覆盖率和满意度尽可能高。建议优先选择以下一种方式：

#### 方式 A：分层优化

1. 先最大化覆盖率。
2. 在覆盖率最优或接近最优方案中最大化满意度。
3. 必要时用利润或服务量完成指标作辅助比较。

#### 方式 B：加权目标

\[
\max F = w_c C + w_s \bar{S}
\]

其中：

- \(C\) 为覆盖率。
- \(\bar{S}\) 为加权平均满意度。

若采用加权目标，论文中应说明权重选择依据，并在灵敏度或附录中说明权重变化是否影响方案。

### 6.8 编程实施

```text

```

站点规模组合总数为：

\]

## 7. 阶段三：定价与政府补贴优化

### 7.1 阶段目标

2. 计算政府补贴。
3. 约束利润率处于保本微利区间。
4. 输出价格满意度、总满意度、年度利润和利润率。

### 7.2 阶段输入

- 各站点覆盖的小区与服务需求池。
- 各服务直接支出。
- 基准价格口径。
- 补贴规则与每日补贴上限。
- 满意度规则。

### 7.3 决策变量

紧急救助公益免费，不作为定价变量。基础决策变量为 5 项付费服务价格：

1. 助餐。
2. 日间照料。
3. 上门护理。
4. 康复理疗。
5. 助浴。

题目允许每个服务站自主定价。严格方案可使用：

\[
p_{j,s}
\]

表示站点 \(j\) 对付费服务 \(s\) 的定价。

若比赛时间要求简化为统一定价，则必须在假设中说明，并分析该简化的局限性。

### 7.4 定价作用链

价格影响价格满意度 \(S_3\)，价格满意度影响总满意度，总满意度再影响实际有效服务人次：

\[
\text{价格} \rightarrow S_3 \rightarrow S \rightarrow \text{实际有效服务人次}
\]

需注意：

- 价格满意度是分段函数，不是光滑连续函数。
- 当价格不高于基准价时，价格满意度已达到最高档位，继续降价不再提高 \(S_3\)。
- 降价可能提升满意度，但会压缩服务利润。

### 7.5 补贴核算

除紧急救助外，其他服务按实际有效服务人次补贴 2 元/人次。对站点 \(j\)：

\[
subsidy_j^{day}=
\min\left(
2 \times effective\_visits_j^{paid},
subsidy\_cap_j^{day}
\right)
\]

补贴上限根据站点规模确定：

| 规模 | 每日补贴上限 |
| --- | --- |
| 小型 | 1000 元 |
| 中型 | 1800 元 |
| 大型 | 2600 元 |

### 7.6 利润率约束

利润率按题目口径核算，并控制在保本微利区间：

\[
0 \leq
\frac{\text{服务总利润}+\text{政府补贴}-\text{年运营成本总额}}
{\text{年运营成本总额}}
\leq 8\%
\]

利润核算应明确：

- 单次收入。
- 单次直接支出。
- 紧急救助只有直接支出，没有定价收入与补贴。
- 固定运营成本。
- 建设折旧是否已纳入成本总额。

### 7.7 求解实施

由于价格满意度为分段规则，建议优先使用可解释搜索：

1. 构造价格候选集合或网格。
2. 过滤不满足利润率约束的价格方案。
3. 计算每个方案下的满意度、有效人次、补贴和利润。
4. 选择满足约束且全局满意度最高的方案。

如果采用连续优化库或启发式算法，应说明：

- 价格边界。
- 初始值。
- 可行性修复或约束处理方式。
- 收敛结果如何复核。

### 8.5 推荐分析指标

建议使用：

1. 相对变化率：

   \[
   \Delta_x = \frac{x'-x}{x}
   \]

2. 参数敏感度：

   \[
   Sen = \frac{\Delta \text{输出指标}/\text{输出指标}}
   {\Delta \text{输入参数}/\text{输入参数}}
   \]

3. 站点集合相似度：

   \[
   J(A,B)=\frac{|A\cap B|}{|A\cup B|}
   \]

其中 \(A\) 和 \(B\) 分别为基准方案与扰动方案的站点集合。

### 8.6 现实不确定性建议

3. 各小区真实通行时间与直线或表格距离不完全一致。
4. 政府补贴政策可能调整。
5. 服务质量差异可能改变满意度与复购行为。
