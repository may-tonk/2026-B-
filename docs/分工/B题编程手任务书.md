# 2026 电工杯 B 题编程手任务书

## 1. 角色定位

编程手负责把题目附件、数学模型和场景参数转化为可复现的计算流程，并产出论文可用的表格、图形数据和支撑材料。

核心要求：

- 不让数据读取散落在主程序中。
- 不让关键参数手工藏在多个脚本里。
- 不让结果表无法复现。

## 2. 总体交付

编程手应交付：

1. 数据加载与校验模块。
2. Q1 人口预测与需求计算模块。
3. Q2 站点选址求解模块。
4. Q3 定价补贴求解模块。
5. Q4 场景重算模块。
6. 结果表、图表数据和运行脚本。
7. 必要测试与约束断言。

## 3. 推荐代码组织

```text
src/
|-- data_loader.py
|-- config.py
|-- q1_forecast.py
|-- q2_location.py
|-- q3_pricing.py
|-- q4_sensitivity.py
|-- metrics.py
`-- utils.py

scripts/
|-- run_q1.py
|-- run_q2.py
|-- run_q3.py
`-- run_q4.py
```

## 4. 阶段 0 任务：数据管道

### 4.1 读取与清洗

负责读取附件 1-5 的 8 张核心工作表。

必须处理：

- 多余标题行。
- 列名前后空格。
- 空白行和空白列。
- 单位字段统一。
- 缺失值检查。

### 4.2 数据对象

至少输出：

| 对象 | 用途 |
| --- | --- |
| `communities` | 小区基础信息 |
| `initial_population` | Q1 初始老人结构 |
| `transition_matrix` | Q1 状态转移 |
| `demand_rates` | 服务需求频次 |
| `service_prices` | 服务价格口径 |
| `direct_costs` | 单次直接支出 |
| `spending_caps` | 消费上限比例 |
| `distance_matrix` | 原始距离 |
| `coverage_mask` | 1000 米覆盖关系 |
| `station_specs` | 成本、容量、补贴上限 |

### 4.3 数据校验

至少写断言或测试：

- 距离矩阵对称。
- 距离矩阵对角线为 0。
- 小区编号完整。
- 老人分类人数加总正确。
- 转移矩阵每行和为 1。
- 站点参数非负。

## 5. 阶段 1 任务：Q1 程序

### 5.1 核心函数

实现：

```text
forecast_population()
compute_theoretical_demand()
apply_consumption_constraint()
convert_monthly_to_daily()
```

### 5.2 输出表

至少输出：

1. 第 1-5 年老人结构预测表。
2. 第 5 年理论月需求表。
3. 第 5 年消费约束后月需求表。
4. 第 5 年消费约束后日需求矩阵。

### 5.3 程序核验

必须检查：

- 消费约束后需求不大于理论需求。
- 新增老人只加到自理状态。
- 需求矩阵维度适配 10 小区和 6 服务项。

## 6. 阶段 2 任务：Q2 程序

### 6.1 全局布局搜索

实现：

- `itertools.product` 或等价方式生成站点状态组合。
- 预算剪枝。
- 覆盖关系筛选。
- 小区归属计算。
- 站点容量校验。
- 候选方案排序。

### 6.2 建议函数

```text
generate_layouts()
layout_build_cost()
candidate_stations_for_community()
assign_by_satisfaction()
compute_station_loads()
check_capacity()
evaluate_coverage()
evaluate_satisfaction()
compute_q2_profit()
solve_q2()
```

### 6.3 结果表

至少输出：

| 表 | 内容 |
| --- | --- |
| 站点布局表 | 位置、规模、建设成本 |
| 小区归属表 | 小区、归属站点、距离 |
| 站点负荷表 | 需求、容量、利用率 |
| 满意度表 | 距离、响应、价格、总分 |
| 年利润表 | 收入、直接支出、固定成本、折旧 |

### 6.4 约束复核

对最终方案写校验：

- 总建设成本 `<= 120` 万。
- 所有归属距离 `<= 1000` 米。
- 所有站点负荷 `<=` 容量。

## 7. 阶段 3 任务：Q3 程序

### 7.1 核心函数

实现：

```text
price_satisfaction()
recompute_satisfaction_for_prices()
compute_effective_visits()
compute_subsidy_with_cap()
compute_profit_margin()
search_price_plan()
```

### 7.2 定价搜索

基础建议：

- 先做候选价格网格。
- 先过滤利润率不可行方案。
- 再选满意度最高方案。

### 7.3 输出表

至少输出：

1. 每站最优价格表。
2. 每站补贴表。
3. 每站利润和利润率表。
4. 每小区总满意度表。
5. 每小区价格满意度表。

### 7.4 强制检查

- 紧急救助价格恒为 0。
- 补贴仅对非紧急救助有效服务人次计算。
- 每站补贴不超过该规模每日上限。
- 利润率处于建模手确认的区间。

## 8. 阶段 4 任务：Q4 程序

### 8.1 场景配置

以参数配置切换场景，不手改核心逻辑。

至少支持：

- 基准场景。
- 增长与转移参数扰动。
- 固定管理成本增加 20%。
- 建设预算变为 140 万。

### 8.2 输出对比

生成统一对比表：

- 站点数。
- 位置。
- 规模。
- 覆盖率。
- 平均满意度。
- 定价。
- 补贴。
- 利润率。

## 9. 与其他角色的接口

### 9.1 向建模手回传

每次求解输出都应带：

- 约束检查结果。
- 关键指标。
- 异常情况说明。

### 9.2 向写作手回传

结果文件要尽量直接可引用：

- 表名清楚。
- 字段带单位。
- 图表数据有来源。
- 说明哪个结果是基准场景，哪个是扰动场景。
