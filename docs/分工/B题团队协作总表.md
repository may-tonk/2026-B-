# 2026 电工杯 B 题团队协作总表

## 1. 文档目的

本文档用于把 B 题的阶段任务、角色边界、交付物和交接关系拆清楚。角色分工采用三条主线：

1. 建模手负责数学口径、变量约束、指标体系和模型解释。
2. 编程手负责数据管道、求解器、结果复现和图表数据。
3. 写作手负责论文结构、文字表达、图表组织和提交材料一致性。

三条主线不是相互等待，而是围绕同一数据流并行推进。

## 2. 协作原则

### 2.1 先锁口径再大量产出

以下事项未确认前，不应同时写出多个互相冲突版本：

- 新增老人进入何种健康状态。
- 消费约束后的需求削减规则。
- 月需求转日需求规则。
- 问题 2 的目标排序方式。
- 问题 3 是每站独立定价还是统一定价。
- 利润、折旧、补贴的核算口径。

### 2.2 结果文件必须有唯一来源

建议统一约定：

| 内容 | 唯一来源 |
| --- | --- |
| 基础参数 | 数据管道与配置文件 |
| Q1 预测结果 | Q1 运行输出 |
| Q2 站点方案 | Q2 求解输出 |
| Q3 定价与补贴 | Q3 求解输出 |
| Q4 对比数据 | Q4 场景输出 |

写作手不得手填一个与代码结果不一致的新数字；编程手也不得在论文定稿后悄悄改口径。

### 2.3 每次交接要同时交三样东西

每个阶段的交付应包含：

1. 数据表或结果文件。
2. 指标解释。
3. 可复现入口或计算说明。

例如，Q2 输出不能只说“建 A、D、G 三个站”，还应给出：

- 站点规模。
- 覆盖小区。
- 覆盖率。
- 满意度。
- 容量利用率。
- 预算核验。
- 结果由哪个脚本产生。

## 3. 总体分工矩阵

| 阶段 | 建模手主责 | 编程手主责 | 写作手主责 | 阶段交付 |
| --- | --- | --- | --- | --- |
| 阶段 0 数据基建 | 假设、指标、符号口径 | 数据读取、清洗、校验、配置 | 问题重述、假设、符号、数据预处理骨架 | 标准数据对象、假设清单 |

| 阶段 2 Q2 | 选址模型、目标、约束、利润指标 | 全局搜索、归属分配、容量校验 | Q2 模型、算法复杂度、方案解释 | 站点网络方案 |
| 阶段 3 Q3 | 定价模型、补贴约束、利润率 | 价格搜索、补贴核算、满意度重算 | Q3 模型、结果分析、可及性分析 | 定价和财政结果 |

## 4. 阶段交接链

```text
阶段 0 标准参数
    -> 阶段 1 第5年人口与消费约束后需求
        -> 阶段 2 站点位置、规模、小区归属

```

## 6. 建议协作节奏

### 6.1 第一轮同步

目标：锁定地基。

必须完成：

- 数据字段清单。
- 假设清单。
- 变量符号草表。
- Q1 递推式最终版。
- 论文目录骨架。

### 6.2 第二轮同步

目标：让 Q1 结果流向 Q2。

必须确认：

- 第 5 年人口结果是否合理。
- 消费约束后需求矩阵是否正确。
- 月需求转日需求是否统一。
- Q2 目标采用分层优化还是加权目标。

### 6.3 第三轮同步

目标：冻结 Q2 网络。

必须确认：

- 预算未超。
- 服务半径未违规。
- 站点未超载。
- 覆盖率与满意度计算口径一致。
- 年利润表能追溯。

### 6.4 第四轮同步

目标：定价和补贴收口。

必须确认：

- 紧急救助价格固定为 0。
- 政府补贴上限执行正确。
- 利润率在保本微利区间。
- 每站定价表与满意度表已给写作手。

### 6.5 最终同步

目标：提交前不打架。

必须确认：

- 论文数字与输出表一致。
- 附录代码与正文方法一致。
- 场景分析覆盖题设三类扰动。
- 摘要中的结论能在正文找到支撑。

## 8. 冲突处理规则

### 8.1 口径冲突

若论文、公式和代码出现冲突，优先级为：

1. 题目与附件原文。
2. 全队已锁定假设。
3. 可复现代码输出。
4. 论文表述。

### 8.2 结果冲突

若两份结果表数字不同，应先查：

- 是否使用同一参数配置。
- 是否使用同一时间尺度。
- 是否同一版需求矩阵。
- 是否同一版满意度计算。

## 9. 每阶段交付验收表

| 阶段 | 验收问题 |
| --- | --- |
| 阶段 0 | 数据是否能统一加载，字段是否全，假设是否锁定 |
| 阶段 1 | 人口预测和需求矩阵是否可复现 |
| 阶段 2 | 站点方案是否满足预算、半径、容量 |
| 阶段 3 | 定价是否满足补贴与利润率约束 |
| 阶段 4 | 三类题设场景是否分别比较 |
| 提交 | 论文、代码、图表、支撑材料是否一致 |
