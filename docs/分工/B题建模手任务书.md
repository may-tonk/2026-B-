# 2026 电工杯 B 题建模手任务书

## 1. 角色定位

建模手负责把题目语言转化为数学语言，并保证公式、约束、指标和结果解释前后一致。

建模手不是只写公式，也需要持续给编程手提供可实现的规则，给写作手提供可表达的模型逻辑。

## 2. 总体交付

建模手应交付：

1. 假设清单。
2. 符号表。
3. Q1 递推模型与消费约束公式。
4. Q2 决策变量、目标函数、约束体系和算法逻辑。
5. Q3 定价、补贴、利润率模型。
6. Q4 场景设计和鲁棒性评价指标。
7. 模型局限性、改进方向与现实不确定性分析。

## 3. 阶段 0 任务：口径与地基

### 3.1 必做任务

- 明确老人健康状态顺序：

  ```text
  自理 -> 半失能 -> 失能
  ```

- 确认新增老人默认进入自理状态。
- 确认死亡率对三类老人统一处理。
- 确认消费约束按附件要求等比例削减。
- 确认覆盖率、满意度、实际有效服务人次的定义。
- 确认折旧、运营成本、直接支出、补贴在利润核算中的位置。

### 3.2 给编程手的输入

建模手应向编程手提交：

| 输入 | 说明 |
| --- | --- |
| 状态转移矩阵结构 | 行列顺序和转移方向 |
| Q1 递推式 | 新增项与死亡项写法 |
| 消费约束公式 | 削减系数定义 |
| Q2 指标定义 | 覆盖率、满意度、利润 |
| Q3 约束公式 | 补贴上限、利润率区间 |

### 3.3 给写作手的输入

- 假设条目。
- 符号表初稿。
- 模型选择理由。

## 4. 阶段 1 任务：Q1 模型

### 4.1 人口预测模型

完成并确认：

\[
N_{t+1}=(1-d)N_tP+B_t
\]

其中：

\[
B_t=[gT_t,0,0]
\]

需要解释：

- \(P\) 只描述存活老人内部健康状态转移。
- 死亡率单独施加。
- 新增老人为何先归为自理老人。

### 4.2 需求核算模型

完成：

- 单人需求频次矩阵定义。
- 理论需求矩阵公式。
- 消费上限约束公式。
- 比例削减公式。
- 月需求转日需求说明。

### 4.3 Q1 结果审查

拿到编程手输出后检查：

- 老人数变化方向是否合理。
- 三类老人转移是否符合题意。
- 消费约束后需求是否不超过理论需求。
- 表格按小区、按服务、按老人类型是否能解释。

## 5. 阶段 2 任务：Q2 模型

### 5.1 先完成模型定义

建模手必须先写清：

1. 站点位置变量。
2. 站点规模变量。
3. 小区归属规则。
4. 预算约束。
5. 半径约束。
6. 容量约束。
7. 覆盖率定义。
8. 满意度计算。
9. 年利润核算。

### 5.2 目标函数建议

优先选择一种方式并固定：

#### 方案 A：分层优化

- 第一层：最大化覆盖率。
- 第二层：最大化平均满意度。
- 第三层：辅助比较成本、利润或容量余量。

#### 方案 B：加权目标

\[
\max F=w_cC+w_s\bar{S}
\]

若用方案 B，建模手需给出权重解释。

### 5.3 满意度反馈处理

建模手要明确：

- Q2 中价格满意度如何初始化。
- 响应满意度如何由利用率得到。
- 归属与满意度耦合采用一次近似还是迭代求稳。

### 5.4 Q2 结果审查

拿到站点方案后检查：

- 是否违反预算。
- 是否存在超 1000 米服务关系。
- 是否有超容量站点。
- 是否把覆盖率误写成服务人次比例。
- 利润表是否漏掉折旧或固定成本。

## 6. 阶段 3 任务：Q3 模型

### 6.1 定价模型定义

必须明确：

- 紧急救助公益免费。
- 仅 5 项付费服务进入价格变量。
- 每站独立定价还是全区域统一定价。
- 价格满意度为分段函数。

### 6.2 补贴与利润约束

完成：

\[
subsidy_j^{day}=\min(2 \times visits_j^{paid}, cap_j)
\]

以及：

\[
0 \leq \text{利润率} \leq 8\%
\]

### 6.3 可及性分析框架

问题 3.3 应分别分析：

| 老人类型 | 重点 |
| --- | --- |
| 自理老人 | 助餐、日间照料、价格敏感性 |
| 半失能老人 | 护理、康复、助浴需求增加 |
| 失能老人 | 需求强度高、支付约束与地理可及性更敏感 |

需要把价格、地理距离、信息或服务能力维度结合起来，不只写价格。

## 7. 阶段 4 任务：Q4 分析

### 7.1 题设场景

确认三类场景分别处理：

1. 老人增长与状态转移参数变化。
2. 日固定管理成本增加 20%。
3. 建设预算改为 140 万。

### 7.2 评价指标

建模手应提供：

- 相对变化率。
- 敏感度解释。
- 站点集合相似度或方案变化描述。
- 鲁棒性结论判据。

### 7.3 现实不确定性

至少准备 3 类现实不确定因素及应对策略。

## 8. 与其他角色的接口

### 8.1 对编程手

建模手交公式时必须同时给：

- 变量定义。
- 单位。
- 输入输出维度。
- 约束判定标准。

### 8.2 对写作手

建模手交付章节素材时必须同时给：

- 为什么这样建模。
- 与题意的对应关系。
- 局限性。

## 9. 建模手自检清单

- [ ] 公式与题目用词一致。
- [ ] 新增项没有写错进入状态。
- [ ] 消费削减没有偏离附件规则。
- [ ] Q2 覆盖率和满意度目标可解释。
- [ ] Q3 紧急救助未进入定价变量。
- [ ] 灵敏度场景没有混成单一场景。
- [ ] 局限性与当前模型假设一一对应。
