# 2026 电工杯 B 题算法应用说明

## 1. 文档目的

本文档单独说明本项目会用到的主要算法、这些算法解决什么问题、为什么适合本题、在哪个阶段使用，以及落地时应注意的实现边界。

本项目中的算法不应被当作论文装饰。每一种算法都应服务于一个明确任务：

- 预测未来老人结构。
- 把服务需求与支付能力约束接起来。
- 在预算、半径、容量约束下寻找站点方案。
- 在补贴与利润率约束下搜索定价方案。
- 对参数扰动后的方案变化进行量化比较。

## 2. 推荐算法路线

本项目建议优先采用下表中的算法路线。选择原则不是追求算法名称复杂，而是保证：

1. 与题目和附件给出的规则一致。
2. 能复用当前项目已经完成的数据矩阵、覆盖矩阵和满意度规则配置。
3. 能输出论文需要解释的中间结果，而不是只给出一个黑箱最优值。

### 2.1 建议采用算法清单

| 题目环节 | 建议采用算法 | 作用 | 为什么采用 | 使用位置 |
| --- | --- | --- | --- | --- |
| 阶段零 | 数据校验与矩阵化预处理 | 将附件表格转成统一参数对象、矩阵和规则函数 | 后续 Q1-Q4 都要重复调用人口、需求、成本、距离和满意度规则，先标准化可以降低口径错误 | `T0_01_data_loader.py`、`T0_02_validation.py`、后续求解模块输入 |
| 1.1 | 离散状态转移递推 | 预测未来 5 年各小区三类老人数 | 题目直接给出初始老人结构、健康状态转移率、死亡率和新增老人比例，适合按年递推 | `q1_forecast.py` 或 T1 人口预测模块 |
| 1.2 | 矩阵化需求核算 | 由三类老人数计算 6 项理论服务需求 | 附件给出三类老人对各服务的月均需求频次，矩阵乘法最贴合数据结构，便于拆分和核对 | Q1 理论需求计算、Q2 需求输入准备 |

| 2.1/2.2/2.3 | 距离覆盖矩阵 + 多规模站点布局全局枚举 + 预算剪枝 | 搜索站点位置和小、中、大规模组合 | 10 个小区、每点 4 种建站状态，布局上界为 `4^10`，可完整搜索且可解释 | Q2 选址、规模优化、算法步骤与复杂度说明 |
| 2.1/2.3 | 满意度驱动归属分配 | 确定每个小区选择哪个可达站点 | 题目要求老人选择满意度最高的站点，且响应满意度与站点利用率有关，归属必须单独处理 | Q2 小区归属、站点负荷与满意度计算；Q3 固定网络下满意度重算 |
| 2.1/2.3 | 容量可行性校验 + 分层多目标评价 | 过滤超载方案，并比较覆盖率和满意度 | 容量是硬约束；覆盖率和满意度含义不同，先覆盖率后满意度更便于解释 | Q2 候选方案筛选和最优方案排序 |
| 3.1/3.2 | 分段价格候选搜索 + 补贴与利润可行性过滤 | 在补贴上限和保本微利约束下寻找定价方案 | 价格满意度是分段函数，直接围绕基准价和阈值搜索更稳，也便于复核利润率 | Q3 定价、补贴核算、利润率筛选 |
| 3.3 | 分类可及性指标对比分析 | 比较定价和补贴对三类老人服务可及性的影响 | Q3.3 更需要解释不同老人群体是否受益，而不是再引入新的优化层 | Q3 结果分析、论文图表与文字讨论 |
| 4.1/4.2/4.3 | 场景重算 + 相对变化率 + 敏感度系数 + 站点集合相似度 | 量化关键参数扰动后的方案变化和鲁棒性 | 题目已给出明确扰动场景，重算同一模型后比较变化最直接 | Q4 参数扰动、方案比较、鲁棒性评价 |

### 2.2 推荐主线

推荐将模型链写成：

```text
数据标准化
-> Q1 状态递推预测老人结构
-> Q1 矩阵核算理论需求
-> Q1 消费约束比例削减
-> Q2 全局枚举搜索站点布局
-> Q2 满意度归属与容量校验
-> Q3 分段定价与补贴利润过滤
-> Q4 场景重算和敏感度评价
```

该主线的优点是前后输入输出关系清楚：

- Q1 给 Q2 提供消费约束后的日需求。
- Q2 给 Q3 提供站点位置、规模和服务归属。
- Q4 复用 Q1-Q3 的同一求解链，不需要重新发明一套模型。

### 2.3 不建议作为主模型的算法

下列方法可在模型评价或扩展讨论中提及，但不建议替代本项目主线：

| 方法 | 不建议主用的原因 |
| --- | --- |
| 灰色 `GM(1,1)` + 马尔可夫混合预测 | 本题没有多年历史序列，题目已经给出状态转移和新增、死亡规则，离散递推更直接 |
| 带服务优先级的需求截断 | 附件 2 要求消费超限时等比例削减，优先级截断会改变题设规则 |
| `NSGA-II`、模拟退火等启发式选址 | 本题候选布局规模可枚举，黑箱启发式会削弱最优性说明和复现性 |
| 政府与站点双层博弈定价 | 题目给出的是补贴规则与经营约束，没有明确政府可调决策变量，双层结构容易脱题 |
| 熵权-`TOPSIS` 作为 Q3.3 主分析 | 会把机制解释转为指标排序，且权重来源需要额外论证 |
| 正交试验与方差分析作为 Q4 主方法 | 当前是确定性扰动场景，缺少统计重复样本，场景重算与敏感度指标更贴题 |

## 3. 阶段零算法：数据校验与矩阵化预处理

### 3.1 用途

附件是面向阅读的 Excel 表格，而后续模型需要稳定的矩阵和参数对象。数据预处理的算法价值在于：

1. 清洗格式。
2. 检查字段完整性。
3. 将表格映射为可计算对象。
4. 将题目硬约束提前编码。

### 3.2 项目使用位置

用于 `DataLoader` 或同等数据入口模块。

### 3.3 主要输出

| 输出 | 算法角色 |
| --- | --- |
| `population_matrix` | Q1 初始状态 |
| `transition_matrix` | Q1 健康状态递推 |
| `demand_rate_matrix` | Q1 理论需求核算 |
| `distance_matrix` | Q2 距离满意度 |
| `coverage_mask` | Q2 半径约束 |
| `station_specs` | Q2、Q3 成本容量 |
| `satisfaction_rules` | Q2、Q3 满意度计算 |

### 3.4 实施要点

#### 3.4.1 维度校验

应使用断言或测试核对：

- 小区为 10 个。
- 距离矩阵为 10x10。
- 需求项目为 6 项。
- 老人状态为 3 类。
- 站点规模为 3 类。

#### 3.4.2 覆盖矩阵

把 1000 米服务半径转为二值关系：

\[
cover_{ij}=
\begin{cases}
1, & distance_{ij} \leq 1000 \\
0, & distance_{ij} > 1000
\end{cases}
\]

它用于快速判断小区 \(i\) 是否可能由站点 \(j\) 服务。

### 3.5 为什么使用

本题后续优化会大量重复调用距离、成本、容量、满意度和需求数据。先矩阵化可以：

- 降低重复读取错误。
- 降低模型函数耦合。
- 为问题 4 的场景重算留出配置入口。

## 4. 问题 1 算法：离散状态转移递推

### 4.1 用途

预测每个小区未来 5 年老人结构变化。

### 4.2 为什么适合本题

题目明确给出：

- 当前三类老人数。
- 年度健康状态转移概率。
- 年死亡率。
- 年新增老人比例。

这些信息天然适合构造按年迭代的离散递推模型。

### 4.3 模型结构

状态顺序：

```text
[自理, 半失能, 失能]
```

状态转移矩阵：

\[
P=
\begin{bmatrix}
1-p_{12} & p_{12} & 0 \\
0 & 1-p_{23} & p_{23} \\
0 & 0 & 1
\end{bmatrix}
\]

第 \(t\) 年状态：

\[
N_t=[A_t,H_t,D_t]
\]

第 \(t\) 年总老人数：

\[
T_t=A_t+H_t+D_t
\]

新增项：

\[
B_t=[gT_t,0,0]
\]

年度递推：

\[
N_{t+1}=(1-d)N_tP+B_t
\]

### 4.4 项目使用位置

- `q1_forecast.py`
- 问题 1.1
- 问题 4 中增长率与转移概率扰动场景

### 4.5 伪代码

```python
state = initial_state
history = [state]

for year in range(5):
    total = state.sum()
    births = np.array([growth_rate * total, 0.0, 0.0])
    state = (1 - death_rate) * state @ transition_matrix + births
    history.append(state)
```

### 4.6 输出

- 每个小区第 1 年到第 5 年三类老人数。
- 第 5 年人口结构矩阵。

### 4.7 注意事项

1. 若新增项写成 `state * growth_rate`，就违背新增老人全部进入自理状态的假设。
2. 若把死亡率写进 \(P\)，需要重新解释矩阵行和；基础模型建议将死亡率单独处理。
3. 输出展示时可以取整，但中间计算可保留小数。

## 5. 问题 1 算法：矩阵化需求核算

### 5.1 用途

将第 5 年三类老人数转换为 6 项服务的理论需求量。

### 5.2 算法结构

设：

- \(N_i\)：小区 \(i\) 的三类老人数量行向量。
- \(R\)：3 类老人对 6 项服务的单人月需求矩阵。

则：

\[
Q_i^{theory}=N_iR
\]

### 5.3 项目使用位置

- 问题 1.2。
- 问题 2 输入准备。

### 5.4 为什么使用矩阵乘法

矩阵乘法能够统一处理：

- 10 个小区。
- 3 类老人。
- 6 项服务。

相比手写循环更容易核对维度，也便于后续输出按小区、按服务、按老人类型的拆分结果。

### 5.5 注意事项

- 若论文要展示按老人类型的需求，不能只保留总需求矩阵。
- 应保留理论需求与消费约束后需求两份结果。

## 6. 问题 1 算法：消费约束比例削减

### 6.1 用途

当理论服务费用超过老人可承受的月消费上限时，将需求调整到题目允许的消费范围内。

### 6.2 为什么采用比例削减

附件 2 明确要求：

> 若某类老人的理论服务费用总额超过消费上限，则等比例削减各类服务次数。

因此基础模型必须采用比例削减，而不是自定义服务优先级背包分配。

### 6.3 算法结构

对小区 \(i\)、老人类型 \(k\)：

1. 计算理论费用 \(E_{ik}\)。
2. 计算消费上限 \(L_{ik}\)。
3. 计算削减系数：

   \[
   \lambda_{ik}=\min(1,L_{ik}/E_{ik})
   \]

4. 各项需求同比例缩放。

### 6.4 项目使用位置

- 问题 1.3。
- 问题 2 的需求输入。

### 6.5 伪代码

```python
expense = demand_rates @ service_prices
limit = income * spending_cap_ratio
scale = min(1.0, limit / expense)
constrained_rates = demand_rates * scale
```

### 6.6 注意事项

- 比例削减是需求约束，不是价格优化。
- 紧急救助是否参与消费支出应与全队价格口径保持一致，并在论文中说明。
- 基础阶段不应改为“先保障助餐和紧急救助”的背包截断。

## 7. 问题 2 算法：覆盖矩阵与设施选址搜索

### 7.1 用途

在 10 个可选小区中寻找服务站位置和规模组合，使方案满足预算、服务半径与容量约束，并尽量提高覆盖率和满意度。

### 7.2 为什么本题可用全局枚举

每个小区只有 4 种状态：

```text
不建、小型、中型、大型
```

总布局数：

\[
4^{10}=1,048,576
\]

该规模对现代计算机可接受，且预算剪枝后可行方案会显著减少。相比直接使用黑箱启发式算法，全局枚举更有利于：

- 保证在既定评价规则下搜索完整。
- 解释算法流程。
- 输出确定的最优方案。

### 7.3 项目使用位置

- 问题 2.1。
- 问题 2.2。
- 问题 2.3。
- 问题 4 的重新选址。

### 7.4 主要流程

1. 生成站点-规模组合。
2. 用预算约束快速剪枝。
3. 用覆盖矩阵判断各小区可达站点。
4. 按满意度规则确定归属。
5. 校验容量。
6. 计算覆盖率、满意度、有效服务人次和利润。
7. 在可行方案中选择最优方案。

### 7.5 伪代码

```python
best_solution = None

for layout in all_station_layouts:
    if build_cost(layout) > budget:
        continue

    if not every_required_community_has_candidate(layout, coverage_mask):
        continue

    assignments = assign_by_satisfaction(layout, demand, distance_matrix)
    station_loads = compute_station_loads(assignments, demand)

    if any_load_exceeds_capacity(station_loads, layout):
        continue

    metrics = evaluate_layout(layout, assignments)

    if better(metrics, best_solution):
        best_solution = pack(layout, assignments, metrics)
```

### 7.6 预算剪枝

预算剪枝用于尽早过滤不可能方案：

\[
\sum_j cost(scale_j) \leq budget
\]

预算剪枝应在满意度与容量评估前执行，以减少后续计算量。

### 7.7 半径剪枝

若某小区没有任何 1000 米内站点，则该小区无法被该布局覆盖。根据目标设计，可以：

- 直接保留并让覆盖率下降。
- 在追求全覆盖或覆盖率阈值时剪除。

具体采用哪种方式应与问题 2 的目标函数一致。

### 7.8 时间复杂度说明

若每个候选布局评价成本记为 \(E(n)\)，候选小区数为 \(n=10\)，规模状态数为 4，则布局枚举上界为：

\[
O(4^nE(n))
\]

对本题 \(n=10\)，上界为约一百万种布局。由于预算剪枝、覆盖关系预处理与向量化计算，实际评价数量会显著减少。

### 7.9 注意事项

1. “布局枚举完成”不等于“小区归属自动正确”，归属必须按满意度规则处理。
2. 若站点超载，基础模型建议将该方案判为不可行，而不是随意丢弃超出需求。
3. 若采用加权目标，权重变化可能影响最优布局，应留出敏感性说明。

## 8. 问题 2 算法：满意度驱动归属分配

### 8.1 用途

确定每个小区老人最终选择哪个可达服务站。

### 8.2 为什么需要单独处理

题目规定老人只选择满意度最高的服务站。满意度不是单纯距离函数，还包含：

- 距离满意度。
- 响应满意度。
- 价格满意度。

其中响应满意度与站点利用率相关，因此归属和满意度之间存在反馈。

### 8.3 基础过程

对某一站点布局：

1. 先基于可达站点集合形成候选归属。
2. 根据距离与初始响应评价得到初始满意度。
3. 计算各站点负荷和利用率。
4. 更新响应满意度。
5. 更新综合满意度与归属。
6. 若归属不再变化，则输出稳定归属。

### 8.4 项目使用位置

- 问题 2 的服务分配。
- 问题 3 固定网络下的满意度重算。

### 8.5 可选实现策略

| 策略 | 特点 |
| --- | --- |
| 一次近似 | 计算简单，论文需说明近似 |
| 固定点迭代 | 更贴合利用率反馈 |
| 全量小规模搜索 | 若归属候选少，可搜索归属组合 |

在本题规模下，建议优先实现固定点迭代或清晰的一次近似，并做结果核验。

### 8.6 注意事项

- 若多个站点满意度并列，要定义稳定 tie-break 规则。
- 覆盖率按老人数量口径核算，不能只看服务人次。

## 9. 问题 2 算法：多目标评价

### 9.1 用途

在同时追求覆盖率与满意度时比较候选站点方案。

### 9.2 两种推荐方式

#### 9.2.1 分层优化

先比较覆盖率，再比较满意度：

```text
覆盖率更高 -> 更优
覆盖率相同 -> 满意度更高者更优
仍相同 -> 利润、服务量完成率或建设成本作辅助比较
```

#### 9.2.2 加权评价

\[
F=w_cC+w_s\bar{S}
\]

其中：

- \(C\)：覆盖率。
- \(\bar{S}\)：平均满意度。

### 9.3 项目使用位置

- 问题 2 方案排序。
- 问题 4 不同场景下方案比较。

### 9.4 建议选择

基础版建议先采用分层优化，因为：

- 题目把覆盖率作为明确服务目标。
- 覆盖率与满意度量纲和社会含义不同。
- 分层优化更便于解释最优方案选取过程。

若采用加权评价，应记录权重，并对权重选择给出说明。

## 10. 问题 3 算法：分段价格搜索

### 10.1 用途

在选址网络固定后，为 5 项付费服务寻找满意度尽可能高且利润率、补贴约束可行的价格方案。

### 10.2 为什么不用纯黑箱连续优化起步

附件 5 的价格满意度是分段变化的。价格变化在很多区间内不会改变价格满意度档位，因此目标函数可能出现：

- 台阶型变化。
- 可行区间断裂。
- 同一满意度下利润差异很大。

在这种情况下，先做可解释的离散候选价搜索更稳。

### 10.3 项目使用位置

- 问题 3.1。
- 问题 3.2。
- 问题 4 的重新定价。

### 10.4 候选价格搜索思路

对每个付费服务构造候选价格：

1. 基准价以下合理区间。
2. 基准价。
3. 高于基准价 10% 档位边界附近。
4. 高于基准价 20% 档位边界附近。
5. 若利润约束需要，可补充保本临界附近候选点。

如果采取每站独立定价，则候选价格维度为：

\[
\text{站点数} \times 5
\]

需通过：

- 减少候选点数量。
- 分站搜索。
- 局部细化。

控制组合规模。

### 10.5 伪代码

```python
best_price_plan = None

for price_plan in candidate_price_plans:
    satisfaction = recompute_satisfaction(price_plan, fixed_network)
    effective_visits = demand * satisfaction
    subsidy = compute_subsidy_with_caps(effective_visits)
    profit = compute_profit(price_plan, effective_visits, subsidy)

    if not margin_in_range(profit):
        continue

    if satisfaction_better(satisfaction, best_price_plan):
        best_price_plan = pack(price_plan, satisfaction, subsidy, profit)
```

### 10.6 注意事项

1. 紧急救助价格固定为 0。
2. 补贴只对非紧急救助的实际有效服务人次核算。
3. 补贴上限按站点规模逐日限制。
4. 价格满意度达到最高档后，继续降价不再提升该子分数。

## 11. 问题 3 算法：补贴与利润可行性过滤

### 11.1 用途

将政策约束与经营约束转为价格方案筛选条件。

### 11.2 项目使用位置

- 问题 3 价格方案筛选。
- 问题 4 成本上升后的重新定价。

### 11.3 核算逻辑

每个价格方案都应执行：

1. 服务收入计算。
2. 单次直接支出计算。
3. 紧急救助直接成本计算。
4. 固定运营成本计算。
5. 建设折旧成本计算。
6. 政府补贴计算。
7. 利润率判断。

### 11.4 为什么单独做过滤

满意度最高的价格方案可能不保本；利润最高的方案又可能压低价格满意度。先形成可行价格集合，再在其中优化满意度，能让模型逻辑更清楚。

## 12. 问题 3 分析方法：分类可及性指标对比

### 12.1 用途

分析定价和政府补贴方案对自理、半失能、失能三类老人的服务可及性影响。

### 12.2 为什么采用

问题 3.3 的重点是解释不同老人群体在定价方案下的受益程度和潜在负担差异，而不是再次求一个新的选址或定价最优解。分类可及性指标对比有三个优点：

1. 直接复用 Q1 的分类型需求、Q2 的覆盖归属和 Q3 的价格满意度结果。
2. 能把“服务能否到达”“需求能否转化为有效服务”“价格是否形成负担”分开解释。
3. 指标含义清楚，便于在论文中用表格和图形对三类老人作横向比较。

### 12.3 项目使用位置

- 问题 3.3。
- Q3 结果解释章节。
- 模型评价中关于公平性和服务可及性的讨论。

### 12.4 推荐指标

建议至少比较三类老人在下列指标上的差异：

| 指标 | 作用 |
| --- | --- |
| 覆盖老人数量或覆盖率 | 说明三类老人是否进入 Q2 服务网络 |
| 消费约束后需求量 | 说明三类老人真实进入后续优化的需求规模 |
| 实际有效服务人次 | 说明满意度折减后有多少需求真正转化为服务 |
| 有效服务完成比例 | 比较 `实际有效服务人次 / 消费约束后需求` |
| 平均综合满意度与价格满意度 | 解释定价方案对不同老人群体的感受差异 |
| 服务支出负担率 | 比较定价后服务支出与消费上限或收入的关系 |

若某一类老人在多个小区分布不同，满意度宜按该类老人的需求量或人数加权汇总，不宜直接对小区满意度做简单平均。

### 12.5 注意事项

1. Q3.3 可配合柱状图、雷达图或对比表展示，但不必把分类分析强行改造成新的综合排序模型。
2. 若使用公平性类指标，应写清权重口径和分母定义。
3. 若采用统一定价简化，应说明不同老人类型的差异主要来自需求结构、收入约束和站点覆盖，而非站点间价格差异。

## 13. 问题 4 算法：场景重算与敏感度量化

### 13.1 用途

观察关键参数变化后，站点与定价方案是否稳定。

### 13.2 项目使用位置

- 问题 4.1。
- 问题 4.2。
- 问题 4.3。

### 13.3 场景重算

对每个场景：

1. 更新参数配置。
2. 若人口增长或转移概率变化，重新运行 Q1。
3. 重新运行 Q2 选址。
4. 固定新网络后重新运行 Q3 定价。
5. 输出与基准场景同口径指标。

### 13.4 推荐指标

#### 13.4.1 相对变化率

\[
\Delta_x=\frac{x'-x}{x}
\]

用于比较覆盖率、满意度、补贴、利润等指标变化。

#### 13.4.2 敏感度系数

\[
Sen=
\frac{\Delta y / y}
{\Delta p / p}
\]

用于描述输出指标对输入参数的相对敏感程度。

#### 13.4.3 站点集合 Jaccard 相似度

\[
J(A,B)=\frac{|A\cap B|}{|A\cup B|}
\]

其中：

- \(A\)：基准场景站点集合。
- \(B\)：扰动场景站点集合。

该指标用于描述站点网络拓扑稳定性。

### 13.5 不建议默认使用的统计方法

若每个场景只有一套优化结果，不建议直接用方差分析作为主方法。原因是：

- 样本重复不足。
- 场景并非随机试验样本。
- 变化率、敏感度和方案相似度更直接对应题目要求。
